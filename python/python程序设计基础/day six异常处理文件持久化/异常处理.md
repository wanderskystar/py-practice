一、错误与异常
1. 语法错误：代码书写格式错误,程序完全无法运行,解析阶段直接报错,不能用try捕获。
2. 运行异常：语法没问题,执行过程出错,程序会崩溃;可用try-except捕获,防止程序终止

二、标准完整结构try-except-else-finally(顺序不能乱)
try：监测风险代码
except：捕获对应异常并给出提示；可写多个，精准异常写在前，通用 Exception 写最后
else：程序正常运行后的收尾逻辑（无报错才走）
finally：资源清理专用（关闭文件、断开连接），永远执行

try:
    # 放有可能出错的代码（核心）
    危险代码
except 异常类型1 as e:
    # 匹配类型1出错时执行
    处理1
except 异常类型2 as e:
    # 匹配类型2出错时执行
    处理2
except Exception as e:
    # 通用捕获，捕获大部分普通异常（兜底）
else:
    # 【可选】try代码无任何异常才执行；出错不运行
finally:
    # 【可选】无论是否报错、是否return，一定会执行；用于关闭文件/释放资源

三、 常见内置异常
异常类	触发场景
1. ValueError	值错误，如字母转 int、数字超出规定范围
2. ZeroDivisionError	除数等于 0
3. FileNotFoundError	r 模式打开不存在的文件
4. IndexError	列表 / 元组下标越界
5. KeyError	字典访问不存在的键
6. NameError	使用未定义变量
7. TypeError	类型不匹配，如数字 + 字符串

四、主动抛出异常
1. raise 异常类型("提示文字")
作用：业务逻辑不满足时手动报错，不用等程序自动崩溃
age = -5
if age < 0:
    raise ValueError("年龄不能为负数")

2. assert断言
语法：assert 条件，报错提示
条件为 False 自动抛出 AssertionError，多用于开发测试校验。
score = 120
assert 0<=score<=100, "成绩超出0-100范围"

3. 自定义异常
规则：新建类继承Exception，用于区分业务专属错误
class PaswordShorterr(Exception):
    pass
# 使用
if len(pwd)<8:
    raise PasswordShortError("密码长度不足8位")

五、易错点
1. 捕获顺序：细分异常放前面，通用Exception放最后，否则细分异常永远不会触发；
2. finally 中写 return 会覆盖 try/except 里的返回值，尽量不在 finally 写 return；
3. 语法错误无法被 try 捕获。
